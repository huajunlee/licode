# Recipe 1：审查代码改动

> **目标**：用 LICode 审查你刚写的代码，发现 bug、改进建议和安全问题。
>
> **使用功能**：Agent 对话、read 工具、grep 工具、Thinking 推理

---

## 场景描述

你在 `src/auth.ts` 里完成了一个登录模块，想让人帮你 review 一下。

## 步骤

### 1. 让 LICode 阅读你的改动

```
> 帮我 review 一下 src/auth.ts 的代码，检查是否有安全问题或逻辑错误
```

LICode 会自动：
1. 用 `read` 工具读取 `src/auth.ts`
2. 用 `grep` 搜索相关的引用和依赖
3. 在 Thinking 卡片中分析逻辑

### 2. 观察推理过程

屏幕上方会出现推理卡片，按 `Ctrl+↓` 聚焦，按 `Enter` 展开：

```
▸ 🤔 正在分析逻辑...
   检查了 login() 函数的参数校验...
   发现 password 在日志中明文输出...

▸ 📖 正在读取代码...
   读取 src/auth.ts (120 行)
```

### 3. 查看审查结果

LICode 会列出发现的问题，例如：

```
审查结果：

1. 🔴 安全问题（第 45 行）
   console.log("login attempt:", username, password)
   密码被记录到日志中，建议移除或脱敏。

2. 🟡 改进建议（第 78 行）
   const user = db.find(u => u.name === username)
   find() 在用户不存在时返回 undefined，没有处理空值情况。

3. 🟢 代码风格
   整体结构清晰，类型标注完整。
```

### 4. 让 LICode 修复问题

```
> 帮我把第 1 和第 2 个问题修复一下
```

LICode 会用 `edit` 工具精确替换代码：

```
┌──────────────────────────────────────────────┐
│ ✓ edit  替换 src/auth.ts:45                  │
│   移除明文密码日志                             │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│ ✓ edit  替换 src/auth.ts:78                  │
│   添加空值检查                                 │
└──────────────────────────────────────────────┘
```

---

## 产物说明

| 产物 | 类型 | 存放位置 | 说明 |
|------|------|---------|------|
| 审查报告 | 对话输出 | 终端显示 | LICode 在对话中以 Markdown 列出问题 |
| 修复后的代码 | 文件修改 | `src/auth.ts`（你指定的文件） | LICode 用 `edit` 工具精确替换了 2 处代码 |
| 会话存档 | JSON 文件 | `.licode/sessions/{id}.json` | 完整审查对话和工具调用记录 |

> 💡 这次操作**不会**创建新文件，只修改已有的 `src/auth.ts`。所有操作记录保存在会话 JSON 中。

## 执行前后对比

**执行前**：
```
src/
├── auth.ts          ← 包含明文密码日志 + 空值检查缺失
```

**执行后**：
```
src/
├── auth.ts          ← 移除明文密码日志 + 添加空值检查
```

LICode 只修改了你指定的文件，不影响项目其他部分。

---

## 关键要点

- LICode 不会自动修改文件——它会先告诉你发现了什么，等你确认后再动手
- 用 `Ctrl+↑/↓` 查看推理过程，了解 LICode 是怎么分析的
- 如果 review 范围很大（多个文件），可以分步让 LICode 逐个文件检查
- 审查结果会保存在会话 JSON 中，可以回头查看

---

## 常见问题排查

**Q: LICode 漏掉了某些问题？**
- 尝试描述更具体："检查 XSS 注入风险"比"检查安全问题"更精准
- 可以分维度审查：先检查安全，再检查性能，最后检查代码风格

**Q: LICode 修复后引入了新 bug？**
- 让 LICode 修复后立即跑相关测试：`"修完后跑一下 npm test -- auth"`
- 用 `git diff` 查看具体改了什么，确认无误再提交
